How I Think
Architecture principles
I build by

Decisions I make consistently - grounded in 13+ years of production experience.

01

Seams before features

I design extension points before they're needed - interfaces, not implementations. A second OCR provider or payment gateway shouldn't require touching the core flow.

02

Measure, then optimise

Every performance improvement I've made started with instrumentation. The Traferium 40× gain came from timing logs proving Snowflake writes were the bottleneck - not guesswork.

03

Modular monolith first

New products get a modular monolith with enforced boundaries - one deployment, no distributed system overhead. Extract services when you feel the pain of not having done so.

04

Business rules in the backend

Eligibility, pricing, approval logic - always in the service layer. Testable, version-controlled, consistently applied regardless of which client calls the API.

05

Idempotency by default

In financial and transactional systems, every state-changing operation gets an idempotency key. Networks fail, clients retry, and duplicate transactions are not acceptable.

06

Silent failures are the worst

A system that crashes loudly is better than one that silently returns wrong data. I design jobs with explicit output assertions and observability at every stage boundary.

07

Let duplication teach you

Don't abstract until the pattern is clear. Three similar workflows need to be understood side-by-side before building a generic engine - premature abstraction is harder to undo than duplication.

08

Write decisions down

Every architectural decision gets an ADR - context, options considered, trade-offs. It eliminates repeated debates, accelerates onboarding, and makes code reviews sharper.
